# DotBot

把微信 ClawBot 中已绑定本人的文字和图片消息转给**同一个既有 dot（爱丽丝）**，通过 iLink、owner broker 和 Codex 原生消息房间完成回复。MCP/Tunnel 保留查询与人工回滚能力。

此仓库迁移了原文字转接源码，并加入消息查询、可选图片/音频收发和本地中文语音合成。图片已接入原生直连房间，并启用 broker `--images`；MCP 仍保留原 8 个工具。音频和 TTS 暂未启用。图片手机实收测试状态见 [图片直连](docs/IMAGE_DIRECT.md)。

| 能力 | 本地代码 | 尚待真实验收 |
|---|---|---|
| 微信图片 → dot | broker 下载/解密/校验，原生上传到同一爱丽丝房间；已准确识别测试图 | 真实微信图片入库/上传通过，首条文字实收；图像识别以原生测试图验证 |
| 微信语音 → dot | 暂不启用；原生 WAV 文件上传成功，但爱丽丝明确无法听取音频 | 需要先转写；当前不推进 |
| dot 图片 → 微信 | 原生房间附件下载、broker 暂存与图片消息发送；原生回图像素一致 | 真实微信 API 与手机实收通过；大图回传缩放，原图保留未通过 |
| dot 音频 → 微信 | PCM WAV **文件附件**发送 | 手机收到并播放；原生语音气泡未实现 |
| dot 文字 → 本地音频 | `wechat_generate_audio` 用已有 eSpeak NG `cmn` 合成并暂存 | 真人自然度/用户听感未验收；不自动发送 |

源码入口：`service.py` 为 stdio MCP；`ilink_broker.py` 独占本人绑定与私有消息库；`media_adapter.py` 处理媒体、缓存和幂等；`local_tts.py` 使用固定隔离子进程合成中文 WAV。文字模式提供 8 个工具、2 个事件，支持按 ID、分页和待回复消息查询；媒体模式增加四个工具，总计 12 个工具、2 个事件。查询参数及回复状态见 [消息查询接口](docs/MESSAGE_QUERIES.md)；合成 sandbox 模式继续可用。

Cloudflare DoH 在进程内按 A/AAAA 分别缓存已验证的公网地址，取地址及 CNAME 的最短 TTL，扣除 HTTP `Age` 和查询耗时，最多缓存 300 秒；TTL 无效、空结果和失败不缓存，也不回退到过期地址。并发查询共用一次解析。事件出口配置不变时复用传输对象，但每次操作仍重读配置；禁用、缺失、无效或变更配置会丢弃旧缓存。重启后首次查询为冷缓存。

dot 网关已实现 broker 持久队列、原生房间提交/订阅、回复父消息关联、恢复、分片及运维命令，并通过真实爱丽丝房间协议测试。当前新文字消息已切换为需桌面进程存活的原生客户端复用模式；手机实收及重启去重已验证；本轮各 10 条同组数字请求的中位数由 32.52 秒降至 12.21 秒（62.5%），初测漏转问题已修复并重新验证。详见 [实测结果](docs/LATENCY_COMPARISON_2026-10-10.md)。状态、部署与回滚见 [直连接入说明](docs/DIRECT_GATEWAY.md)。

离线测试：

```sh
python3 -B -m unittest discover -v
```

Python 测试依赖版本见 `requirements-test.txt`。完整测试含真实本地 eSpeak NG 库和临时 Unix socket，需要系统已有 `libespeak-ng` 与 `cmn` 数据。测试不读取真实凭据，不联系腾讯/OpenAI，不发送微信。不要通过跳过语音/IPC 测试宣称这些能力通过。
